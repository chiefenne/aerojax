# aerojax – Requirements

Living document, updated after each requirement step.

- **D** – decided
- **L** – planned for later (decided, not in the first stages)
- **P** – possible later (mentioned, not decided)
- **X** – not planned
- **O** – open requirement step, with the current proposal

Status: 2026-10-13, requirement steps 1–6 settled.


## 1. Purpose and scope

- 2D Navier–Stokes / RANS solver for airfoil aerodynamics, companion to
  [PyAero](https://github.com/chiefenne/PyAero).
- Developed as a standalone code first; integration with PyAero later (L4).
- Numerics based on [SU2](https://github.com/su2code/SU2), unless newer,
  demonstrably better algorithms exist.
- Verified against analytic solutions and published numerical and experimental
  reference data for a small set of test cases (O10).
- Software engineering lean but solid: package structure, tests including
  reference solutions, CI.
- Step-by-step development; every stage ends with results that can be tested.


## 2. Decisions

| ID  | Step | Topic | Decision | Notes |
|-----|------|-------|----------|-------|
| D1  | –  | Repository | github.com/chiefenne/aerojax, public from the start, MIT license | |
| D2  | –  | Language, stack | Python + JAX (`jit`), float64 throughout; SciPy for sparse linear algebra; NumPy for mesh preprocessing | Alternatives considered: Numba, PyTorch, NumPy-only. Deciding factor: automatic differentiation |
| D3  | –  | Hardware | CPU first; code kept device-agnostic | Apple Metal ruled out: Metal JAX backends have no float64 |
| D4  | –  | Platforms | macOS x86_64 (Intel iMac, primary), macOS arm64 (M4), Linux | On Intel macOS, JAX is available only via conda-forge (official wheels ended with jaxlib 0.5.0) |
| D5  | 1  | Flow model, initial | Incompressible, SU2 INC formulation: density-based generalization of artificial compressibility, fully coupled; constant density, no energy equation | |
| D6  | 1  | Flow model, later | Compressible solver later; state vector and flux interfaces generic from day one | see L1 |
| D7  | 2  | Discretization | Cell-centered finite volume on unstructured meshes: triangles, quadrilaterals, arbitrary polygons, mixed | Face-based data structure; boundary conditions on boundary faces |
| D8  | 3  | Pressure–velocity coupling | Coupled, density-based (as D5), pseudo-time | Implicit solver needed early |
| D9  | 4  | Time | Steady (pseudo-time) and unsteady (dual time stepping, BDF2) from the start | One residual R(U) with an optional physical-time term |
| D10 | –  | Flow regimes | Euler (inviscid), laminar, RANS | |
| D11 | 5  | Turbulence, first model | Spalart–Allmaras, variant SA-neg (NASA TMR) | SA-neg gives essentially the same results as SA, with more robust numerics |
| D12 | 5  | Turbulence, second model | SST | see L2 |
| D13 | 5  | Transport-equation interface | Generic interface for additional transport equations | Used by SA, SST, transition models, optional scalars |
| D14 | 5  | Wall treatment | Wall-resolved (y+ ≈ 1); no wall functions | |
| D15 | 6  | Transition, initial | Prescribed transition location per surface; SA production switched off upstream | Location e.g. from XFOIL or experiment |
| D16 | –  | Initial conditions | User-specified pressure, velocity, turbulence | |
| D17 | –  | Boundary conditions, scope | Farfield, velocity, pressure, wall, turbulence quantities at inlets and outlets; user-selectable; only physically suitable combinations, checked at setup | Detailed set: O9 |
| D18 | 5  | Transpiration wall | Wall blowing/suction, steady or time-dependent, implemented as a boundary condition (no extra equation) | Detailed set: O9 |
| D19 | –  | Test meshes | Generated by the code for each test case, e.g. channel flow with quadrilateral and triangular meshes at several resolutions | Details: O11 |
| D20 | –  | Plots | Plots of all test results compared with reference data | Library: O11 |


## 3. Planned for later

| ID | Feature | Notes |
|----|---------|-------|
| L1 | Compressible solver | Reuses mesh, gradients, limiters, linear solver and boundary-condition framework. Whether transonic flow is a target is not yet decided (P4) |
| L2 | SST turbulence model | SU2 reference implementation (V1994m / V2003m) |
| L3 | Transition transport model | Candidates: SA-AFT (e^N / N_crit based, 2 extra equations), SA-BCM (algebraic, available in SU2), Langtry–Menter (requires SST). Choice made at that stage, after validation |
| L4 | PyAero integration | Read PyAero-exported `.su2` meshes with boundary markers; airfoil cases; later coupling with PyAero |
| L5 | Further turbulence models | Through D13, e.g. Wilcox k-ω |


## 4. Possible later (not decided)

| ID | Feature | Notes |
|----|---------|-------|
| P1 | Adjoint-based shape optimization | JAX reverse mode (`vjp`); SU2 also uses a discrete adjoint |
| P2 | Additional scalar transport equations | Through D13: passive scalar (e.g. to track blown fluid, D18), energy, species |
| P3 | GPU execution on Linux/CUDA | Kept possible by D3; not tuned |
| P4 | Transonic airfoil cases (e.g. RAE2822) | Depends on L1 |


## 5. Not planned

| ID | Item | Reason |
|----|------|--------|
| X1 | k-ε models | Dropped in step 5; no SU2 reference and no NASA TMR verification data. Could be added later through D13 |
| X2 | Wall functions | Conflicts with wall-resolved PyAero meshes and laminar/transitional flow (D14) |
| X3 | Apple Metal backend | No float64 support |
| X4 | Pressure-based segregated solver (SIMPLE/PISO) | Replaced by D8 |


## 6. Open requirement steps

| ID  | Topic | Current proposal |
|-----|-------|------------------|
| O7  | Spatial numerics | Convective flux: FDS with low-speed preconditioning (SU2 INC). MUSCL reconstruction with Venkatakrishnan limiter. Gradient reconstruction: Green–Gauss / weighted least squares, stencil to be chosen for cell-centered. Viscous face gradient: averaged cell gradients with a correction along the cell-to-cell direction |
| O8  | Solver | Implicit pseudo-time Newton–Krylov. Jacobian-vector products via JAX `jvp`; first-order Jacobian as preconditioner; SciPy sparse linear solvers. Start-up strategy (CFL ramping). Coupling of SA to the mean flow: loose (as in SU2) or fully coupled |
| O9  | Boundary-condition set | No-slip wall, symmetry/slip wall, velocity inlet, total-pressure inlet, static-pressure outlet, farfield, periodic, transpiration wall (D18). SA inflow value via the ν̃/ν ratio. Consistency checks at setup |
| O10 | Test cases, reference data | Plane Couette and Poiseuille (exact; order of accuracy on all mesh types). Blasius flat plate. Lid-driven cavity Re 100/1000 (Ghia, Ghia & Shin 1982; optional). Cylinder: potential flow (inviscid), Schäfer–Turek 2D-1 (Re 20) and 2D-2 (Re 100, unsteady). 2D Taylor–Green vortex (time accuracy). Turbulent channel vs DNS (Moser, Kim & Mansour 1999; Lee & Moser 2015). NASA TMR zero-pressure-gradient flat plate (SA). Candidate validation: SD7003 at Re = 60,000 (laminar separation bubble). References still to be checked |
| O11 | Meshes and I/O | In-code mesh generators (quadrilateral, triangle, polygon, mixed; several refinement levels; NumPy only). `.su2` reader. VTU output for ParaView. Plotting library (matplotlib proposed) |
| O12 | Software setup | conda (conda-forge); Python 3.13 with jax/jaxlib 0.10.2 (tentative: conda-forge has osx-64 builds for py311 and py313). `pyproject.toml`, src layout. pytest with fast/slow markers. ruff. NumPy-style docstrings. GitHub Actions on Linux and macOS arm64. Case input format (TOML or SU2-style `.cfg`). Units and non-dimensionalization. Typical mesh sizes and runtime targets. Stage-0 micro-benchmark JAX vs Numba |
| O13 | Stage plan | Final ordering of implementation stages and their test criteria |
